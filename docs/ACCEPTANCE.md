# 验收用例与测试指南

对应需求文档与 PWA 规范，包含人员权限、余额安全、端到端预约、PWA 系统推送与邮件兜底等完整验收步骤。

> 前置条件：已连接远程 Supabase 项目 `linzi-care`（`bzjsbiafxxgljbdcreqf`），本地运行在 `http://localhost:3002`。

---

## 1. 老板能创建员工和会员账号，能修改余额

| # | 步骤 | 预期 |
|---|---|---|
| 1.1 | 老板登录 `/admin` → 员工管理 → 创建员工账号（填姓名、邮箱） | 弹窗展示邮箱 + 系统生成的随机密码，且**只展示这一次**；新建员工自动关联所有在售服务 |
| 1.2 | 用返回的邮箱/密码登录 | 能进入 `/staff` 员工端 |
| 1.3 | 会员管理 → 创建会员账号（填初始余额 100） | 凭证弹窗展示一次；列表出现该会员，余额 ¥100 |
| 1.4 | 会员管理 → 调整余额 → 「增减金额」-30，事由「消费核销」 | 余额变为 ¥70；「变动记录」中新增一条 `-¥30`，含事由与旧→新余额 |
| 1.5 | 员工管理 → 重置密码 | 弹出新密码仅一次；旧密码立即失效 |
| 1.6 | 任选账号 → 停用 → 再登录 | 登录被拒绝；启用后可恢复登录 |
| 1.7 | SQL 审计：`select * from balance_logs order by created_at desc limit 5;` | 每次调整都有记录，`old_balance` 是变更前的真实值，记录操作员 ID |

## 2. 顾客能浏览服务和商品，完成一次预约

| # | 步骤 | 预期 |
|---|---|---|
| 2.1 | 未登录打开首页 / `/services` / `/shop` / `/shop/[id]` | 正常浏览，服务显示时长、门市价与金色大字会员价，商品显示价格与「到店咨询」 |
| 2.2 | `/book` 选项目 → 选技师 → 选日期时段 | 第 3 步只显示排班内、未冲突的 30 分钟步进时段 |
| 2.3 | 未登录点「确认提交」 | 提示去登录；登录后返回 `/book`，已选的项目/技师/时段**保留** |
| 2.4 | 登录会员提交预约 | 显示预约编号，状态「待确认」，页面出现「开启预约提醒」PWA 授权按钮 |
| 2.5 | `/my` → 我的预约 | 能看到刚提交的预约并可取消，顶部亦提供「开启预约提醒」快捷入口 |
| 2.6 | 老板在 `/admin` 顶部「待确认预约」专区（或 `/admin/calendar`）打开该预约 → 确认接单 | 状态变「已确认」，会员端同步可见 |
| 2.7 | 边界测试：并发/重复提交同一时段 | 事务锁与部分唯一索引拦截，明确报错「该时间段已被预约」 |

## 3. PWA 系统推送与多端适配验收（核心新增）

| # | 步骤 | 预期 |
|---|---|---|
| 3.1 | **Android Chrome 体验**：会员打开 `/my` 或预约成功页，点击「开启预约提醒」 | 浏览器直接调起原生通知权限弹窗；点击允许后按钮状态变为「已开启预约提醒」，`push_subscriptions` 成功写入一条包含 endpoint、p256dh、auth 的记录 |
| 3.2 | **iOS 16.4+ 苹果体验**：在 Safari 中点击「开启预约提醒」 | 自动弹出专用引导弹窗，提示用户「先点击分享 → 添加到主屏幕，再从主屏幕打开」 |
| 3.3 | **iOS Standalone 模式**：从 iPhone 桌面独立图标打开网站并点击开启 | iOS 唤起原生系统级通知权限弹窗，允许后成功完成订阅 |
| 3.4 | **实时通知（Webhook）**：会员提交预约或修改状态 | Database Webhook 触发 `send-push`，老板与技师已订阅设备瞬间收到系统横幅通知 |
| 3.5 | **到期提醒（pg_cron）**：预约开始前 2 小时 | `reminders` 队列表到期，`pg_cron`（每 5 分钟）触发 `send-push`，顾客手机系统弹出提醒横幅（含服务项目、技师、时间） |
| 3.6 | **点击跳转**：点击手机横幅通知 | 手机自动唤醒并打开对应页面（顾客端跳转 `/my`；老板端跳转 `/admin` 接单专区；技师端跳转 `/staff`） |
| 3.7 | **404/410 失效自愈**：卸载应用或重置通知权限导致端点失效 | `send-push` 发送捕获 404/410，自动在数据库中安全删除该无效端点，不影响后续调度 |
| 3.8 | **邮件降级兜底**：若顾客未开启 PWA 推送或推送发送失败 | 系统自动降级调用 Resend 发送中文邮件提醒，`notifications` 记录 channel='email'，状态正确更新，不遗漏提醒 |
| 3.9 | **去重保证**：同一预约在后续周期多次扫描 | 检查 `notifications` 表中已有 `status='sent'` 记录，自动跳过，绝不重复打扰 |

## 4. 不同角色数据权限与余额安全（RLS）

| # | 步骤 | 预期 |
|---|---|---|
| 4.1 | 会员登录直接访问 `/admin` | 重定向到 `/my`；员工访问 `/admin` 重定向到 `/staff`；未登录访问重定向到 `/login` |
| 4.2 | 会员 A 打开 `/my` | 只能看到自己的预约、余额记录与 push_subscriptions，看不到他人的数据 |
| 4.3 | 会员登录后尝试直接修改余额：`PATCH /rest/v1/members` body `{"balance": 999999}` | **彻底拦截**：被数据库触发器 `guard_member_balance_update` 抛出异常拒绝 |
| 4.4 | 员工登录调用 `admin_update_balance` RPC | 拦截并报错「权限不足：仅老板可调整余额」 |
| 4.5 | 普通用户尝试越权读取别人的 push_subscriptions | RLS 拦截，仅返回空集或自己的记录 |

## 5. 预约确认流程与状态机

状态机：`pending → confirmed → arrived → done`，任意非终态可 `cancelled`，`confirmed/arrived` 可 `no_show`；`done / cancelled / no_show` 为终态，禁止再流转。

| # | 步骤 | 预期 |
|---|---|---|
| 5.1 | 顾客在 `/book` 提交预约 | 状态为「待确认」；老板收到 Realtime Toast（含「去确认」直达按钮）+ 提示音 + PWA 系统横幅三重提醒 |
| 5.2 | 老板在 `/admin` 顶部「待确认预约」专区（**常驻入口**，无单时显示空态引导不隐身）或 `/admin/calendar` 点击「确认接单」 | 状态变「已确认」；**顾客自动收到确认通知**（已订阅 → 手机系统横幅，点击跳转 `/my`；未订阅 → Resend 邮件兜底），`notifications` 落库 `type='confirmation'` |
| 5.3 | 同一预约重复确认（先取消再确认等绕行） | `notifications` 去重，顾客**不会收到第二次**确认通知 |
| 5.4 | 技师在 `/staff` 尝试「确认接单」 | **被拒**：「技师仅可执行『到店 / 完成 / 未到店』操作，确认与取消请联系老板」 |
| 5.5 | 技师对自己的客单点「顾客到店」「完成服务」「未到店」 | 正常流转；只能操作分配给自己的单 |
| 5.6 | 老板把 `confirmed` 改回 `pending`（乱序） | **被拒**：「不允许的状态流转：confirmed → pending」 |
| 5.7 | 对已 `done` / `cancelled` / `no_show` 的终态单再做任何流转 | **被拒**：终态保护 |
| 5.8 | 顾客在 `/my` 自行取消 pending/confirmed 的单 | 正常取消；技师单随之释放 |
| 5.9 | **入口可发现性**：无待确认单时打开 `/admin` | 顶部专区仍显示「待确认预约 (0)」与空态引导（"顾客下单后会实时出现在这里"），侧边导航无角标 |
| 5.10 | **角标联动**：有待确认单时浏览任意管理页 | 侧边「仪表盘」出现角标 N；确认/取消后角标**即时**递减归零（本地变更广播，不依赖 Realtime 网络回环） |

## 6. 验收辅助 SQL

```sql
-- 1. 查看 PWA 推送订阅列表
select id, user_id, user_agent, created_at, updated_at from public.push_subscriptions;

-- 2. 查看待处理与已发送的提醒任务队列
select * from public.reminders order by send_at asc limit 10;

-- 3. 查看通知去重与审计记录 (包含 pwa 与 email 两种渠道)
select * from public.notifications order by created_at desc limit 10;

-- 4. 查看当前生效的 pg_cron 自动化调度任务
select jobid, jobname, schedule, active from cron.job;
```
